# Phase 18 Scatter (the phase gate scene)

Generated by `inf_editor_core::samples::phase18_scatter_scene` -- the **composed**
gate scene for Phase 18 (Lumen-class GI + Nanite completion). Everything the phase
built, in one level.

- `Phase18Scatter.inf_lvl` -- the scene. A four-tile `Terrain`, a 5x5 grid of
**standing meshlet slabs**, a `PcgVolume` carrying 102 400 scatter instances, a
small painted `Foliage` patch, a `TimeOfDay` + `SkyAtmosphere` authority running
a 600x clock, an authored sun, and a camera.
- `GroundCover.inf_pcg` -- the scatter graph the volume evaluates on load. Its
instances are a **derived cache**, never persisted in the level (editor
`pcg_evaluate`, shipped/PIE player `evaluate_pcg_volumes`).
- `Dense.inf_mesh` -- **NOT committed here.** The slabs reference
`samples/vgeom-demo/Dense.inf_mesh` **by GUID**
(`samples::VGEOM_DEMO_MESH_GUID`); duplicating a 1 MB mesh binary to give this
sample its own copy would buy nothing but a second thing to keep in sync. The
gate (`runtime/inf-player/tests/phase18_gate.rs`) copies **both** sample
directories into its throwaway project's `Content`, so the cook sees one mesh
and derives one `.inf_vmesh` from it.

## Why the scatter is split PCG + Foliage

A `PcgVolume`'s `evaluated` cache is not persisted -- it is recomputed on load from
the committed `.inf_pcg` -- so 102 400 instances cost the `.inf_lvl` nothing.
`Foliage::instances` **is** persisted, so 100k of those would be a megabyte of
committed level. The bulk is therefore PCG and the `Foliage` entity is a small
16-instance patch that covers the painted path (two palette slots, so both buckets
of the projector's per-primitive-kind split are exercised). The level stays ~15 KB
while the loaded world carries six figures of scatter -- the same "small level,
huge scene" property the vgeom demo has for triangles.

## Why the density field is a constant

The PCG kernel is fully specified, so a constant field makes the instance count
arithmetic rather than luck: 8x8 cells of 32 m, `1.6 * 32^2` budget each -> a 40x40
jittered sub-grid -> `64 * 1600 = 102 400`, pinned as
`samples::PHASE18_SCATTER_INSTANCES`. terrain-demo already gates a noise x slope
sampler; what this sample needs is a *stated* count at the 100k scale, and a count
that moved whenever someone retuned a noise frequency would be a fixture that rots.

## Why the slabs stand up

The dense mesh is a displaced plane. Laid flat (as in vgeom-demo) it occludes
almost nothing; rotated 90 deg about X it is a wall. Occluders are what make the
P18.1 two-pass proof and the P18.5 `occluded` counter non-vacuous -- "occlusion on
is pixel-identical to occlusion off" is trivially true when nothing is occluded.
The terrain's relief (~40 m peak-to-trough over 512 m) is steep for the same
reason: hills put scatter instances behind something.

## The gate (`runtime/inf-player/tests/phase18_gate.rs`)

1. the composed frame trace -- pixels, meshlet residency, GI audit and scatter
audit -- is byte-identical across two fresh renderers over a camera path;
2. cooked == uncooked (PIE == shipping) on the projected trace;
3. the 10.6M-triangle vgeom gate still holds with GI, scatter and streaming all
on -- P18.1's subtractive proof survives composition;
4. the instance-cull counters are real (frustum / occluded / distance / mesh /
impostor all nonzero) and deterministic;
5. the composed frame is inside the frame budget, with per-system costs printed;
6. the golden inventory is exactly the 41 committed PNGs.

Regenerate with `INF_BLESS_SAMPLES=1 cargo test -p inf-editor-core samples`.
