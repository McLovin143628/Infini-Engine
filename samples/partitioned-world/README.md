# Partitioned World (P16.5 gate scene)

Generated by `inf_editor_core::samples::partitioned_world_scene` -- the P16.5 gate
scene for **world partition / level streaming**.

- `PartitionedWorld.inf_lvl` -- the scene (schema v10). ONE document, as the editor
always authors: a 4x4 grid of cubes at the centres of 128 m cells, a `GameMode`
with no spatial component, a sun marked `AlwaysLoaded`, a `Walker` carrying a
`StreamingSource`, and a child of the far-corner prop authored a whole world
away from it. What makes it partitioned is one settings block
(`partition.enabled`), nothing else.
- `PartitionedWorld.inf_part` -- NOT committed. It is DERIVED by the cook (like
`.inf_vmesh`): the cook bins the entities into a persistent cell + 16 grid cells
and writes them to a pack entry whose GUID is a pure function of the level's.

## The doctrine this scene exists to pin

Cell streaming decides which entities EXIST, so residency must be a function of sim
state alone. Wants come from `StreamingSource` entities read at the fixed-step
boundary -- never a camera -- and activation/deactivation happen only at that sync
point, in ascending cell order. Loading may run ahead (the prefetch margin); a cell
that reaches its activation step unloaded blocks the step. So the margin buys
latency and can never move a result.

## The v1 boundaries, stated rather than discovered

- The PERSISTENT cell is the world at step 0: the level builder spawns it BEFORE
blueprint actors bind, so a persistent entity's `ActorClass` ticks normally. An
entity that streams IN does NOT gain a ticking blueprint in v1 (the actor map is
fixed at `RuntimeSim` construction). Mark such an entity `AlwaysLoaded`.
- Runtime-spawned entities are never despawned by streaming; a statically-placed
one is evicted with its BIRTH cell, wherever a script has since moved it.
- A cook-time reference from one cell to another is a cook WARNING, never a
promotion: residency must not depend on the reference graph.
- The editor's in-process Simulate runs the whole document unpartitioned (single
document in v1); PIE and a shipped build both stream, and those two are what the
parity gate compares.

The gate (`runtime/inf-player/tests/partitioned_world.rs`):

1. the cook emits ONE `.inf_part` entry, UNCOMPRESSED, deterministic across
rebuilds, and the cooked `.inf_lvl` carries no entities;
2. two headless runs of the scripted walk produce an identical activation trace;
3. the SAME walk under two DIFFERENT prefetch margins produces a byte-identical
sim trace -- the doctrine, as an executable assertion;
4. PIE == shipping: the cooked-pack path and the editor-document path stream the
same cells to the same sim trace;
5. non-partitioned regression: the platformer sample's pack is byte-identical
whether or not partitioning exists;
6. an entity in a far cell does not exist until the walker approaches -- then it
exists with its authored transform.
