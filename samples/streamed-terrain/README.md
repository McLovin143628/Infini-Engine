# Streamed Terrain (P16.3 gate scene)

Generated by `inf_editor_core::samples::streamed_terrain_scene` -- the P16.3b2 gate
scene for **camera-driven terrain streaming**.

- `StreamedTerrain.inf_lvl` -- the scene (schema v9). Its `Terrain` carries an EMPTY
working set plus `asset = World.inf_terrain`, so the level stays kilobytes while
the world is 256 m x 256 m of paged heightfield. A `Walker` entity is what the
gate scripts across the terrain.
- `World.inf_terrain` -- NOT committed. It is ~100 KB of derived bytes that
`samples::write_streamed_terrain_asset` reproduces exactly, so the gate generates
it into the fixture's Content directory (16x16 level-0 pages of 9^2 samples at
2 m, plus three coarse pyramid levels: 256 -> 64 -> 16 -> 4).

## The doctrine this scene exists to pin

The fixed-step sim's results must never depend on camera-driven residency. Sim
wants (level-0 pages around the sim's own entities) load synchronously at the
fixed-step boundary into the ECS `Terrain`'s data; render wants (the camera's
quadtree cut) load into a separate working set inside the streamer that no entity
references.

The gate (`runtime/inf-player/tests/streamed_terrain.rs`):

1. the cook ships the `.inf_terrain` through the level->terrain edge, UNCOMPRESSED
(streaming-class), so tiles page zero-copy out of the mapping;
2. a headless run over a scripted camera path reproduces a byte-identical
resident-set trace AND rendered-frame (projected terrain) trace across two runs;
3. the SAME scripted sim under two COMPLETELY different camera paths produces a
byte-identical sim trace -- the doctrine, as an executable assertion;
4. PIE == shipping: the cooked-pack path and the editor-doc path stream the same
terrain to the same sim trace and the same resident set.

Regenerate with `INF_BLESS_SAMPLES=1 cargo test -p inf-editor-core samples`.
